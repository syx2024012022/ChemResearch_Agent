# ChemResearch Agent：PPT 版式调试阶段进度

更新日期：2026-08-15

## 本阶段结论

以综述《N-Boryl Pyridyl Anion Chemistry》完成了第一套获得用户认可的可编辑组会 PPTX。当前认可版本为：

`output/nbpa-rebuild-20260815-v5/presentation.pptx`

成品共 12 页，采用用户提供的清华大学基础分子科学中心标准模板，并使用论文 TOC Graphic 与 Figure 1–11。标题、页码、作者、期刊信息和 Agent 新增说明为 PowerPoint 原生可编辑文字；论文 Figure 及裁分后的面板以高清图片嵌入，可移动、缩放、裁切和替换。

本轮证明了预定视觉方向可行，但目前部分版式选择和面板裁分仍是在用户反馈下人工校准完成。下一阶段的核心任务是将这些判断正式变成 Composer 可以自动执行、验证和回归的规则。

## 已确认的通用视觉标准

### 模板与字体

- 默认使用 `assets/templates/chem_group_standard.pptx`。
- 保留深蓝分子横幅、机构标识、白色内容区和页码体系。
- 深蓝横幅内的标题必须使用白色字体并居中。
- 新增英文使用 Arial；新增中文使用黑体（`SimHei`）。
- 中英混排时分别设置字体，不依赖系统自动替换。
- 专业组会默认使用英文；中文或双语由用户在特殊要求中提出。

### 内容与证据

- 禁止纯文字页，每页必须有论文图、反应、机理、谱图或数据证据。
- 可见文字尽量采用论文原文术语和原始科学语气，在不改变含义的前提下压缩。
- 不把 `proposed`、`suggested`、`may` 等不确定表述升级成确定结论。
- Agent 自行归纳而非作者原话的内容应标识为推断并保留来源。
- 首页必须包含论文标题、作者、期刊/DOI 和 TOC Graphic。
- 每页 speaker notes 保留 `[Sources]`；不需要讲稿时不生成讲述正文。

### 图片与页面占用

- 页面以图为主体，文字少且贴近对应证据。
- 图片是否“占满”以有效图形的视觉面积判断，而不是图片容器是否已经全宽。
- 对无需说明的单图或多面板整图，允许图片紧贴白色内容区的上下边界。
- 原始裁图有大面积外围白边时，先安全裁白边再判断布局。
- 不拉伸或变形化学结构，不切断箭头、坐标轴、图例和反应条件。

### 已确认的版式判断

1. **普通单图但页面空**
   - 主图右移并放大，约占页面宽度的 60%–65%。
   - 左侧加入论文正文压缩得到的 1–2 条短说明。
   - 说明可置于浅灰圆形区域中，用于强调和视觉平衡。

2. **多面板整图（A–D、A–E 等）**
   - 识别为完整视觉叙事，不沿用普通单图尺寸。
   - 保留面板顺序和相对关系，不另加侧栏描述。
   - 按高度放大到几乎占满标题栏以下的白色区域。

3. **纵向长图且存在明确面板边界**
   - 沿论文原有分隔线安全裁开。
   - 两个面板优先横向并排并尽量统一视觉高度。
   - 三个面板根据宽高比采用“一侧上下两块、另一侧一块大图”等紧凑组合，避免机械三等分导致全部过小。

4. **两图横向排列**
   - 优先统一视觉高度。
   - 重要证据图可以获得更大宽度，例如 Hammett 拟合图。
   - 不机械二等分画布。

5. **机理/表征与拓展应用**
   - 两者承担不同叙事任务且各自素材充足时必须拆页。
   - 不为了满足较少页数而把两个复杂 Figure 缩小后强行并排。

6. **反应、机理和底物范围**
   - 长反应路线和机理沿自然方向铺开。
   - 反应与 scope 适合“上方总反应、下方底物矩阵”。
   - 总结页仍需使用代表性反应、机理或 TOC Graphic，不使用纯文字 bullet 页。

## 当前工程状态

- PDF 解析：PyMuPDF 路线可提取正文、TOC Graphic 和 Figure 1–11。
- Literature Skill：已有证据模型和无来源结论约束。
- 需求交互：已有逐步问答服务，页数使用范围而非精确时长。
- Planning：需求提交后生成规划，必须经用户批准才能进入 Composer。
- Composer：已有模板注册、证据绑定、无纯文字页门禁和来源 notes。
- Renderer：使用 `@oai/artifact-tool` 输出可编辑 PPTX、逐页 PNG、布局 JSON 和 montage。
- Validator：可检查页数、来源、图片存在性、标题换行和页面边界。
- 当前 Python 回归测试：24 项通过（此前验证结果）。
- 当前认可 PPTX 的布局检查：12 页，无越界元素、无标题换行；新增可编辑英文均为 Arial。

## 尚未完全自动化的部分

- Composer 还不能稳定根据 Figure 内部的 A/B/C 面板自动分类版式。
- 面板分隔线和安全裁剪位置目前仍有人工判断成分。
- “机理/表征”和“应用/scope”是否应该拆页，尚未形成完整的语义分类器。
- 目前只使用一篇熟悉的综述校准，尚未证明对陌生原始研究论文同样可靠。
- 视觉验证能检查边界和标题，但还不能完全自动判断“页面体感过空”“重点图不够大”或“叙事组合不合理”。
- 交互过程已有后端服务，但还没有比赛演示用的按钮式前端。
- 比赛接口文档的最终封装、错误处理和部署方式仍需完成验收。

## 建议的下一步

### 第一优先级：把本轮人工判断变成 Composer 规则

- 为 Figure 增加宽高比、面板数量、面板边界和视觉密度特征。
- 新增 `single_with_callout`、`multipanel_full`、`two_panels_fill`、`panel_triptych`、`weighted_two_images` 等正式模板规格。
- 在 Planning/Composer 中加入“叙事任务不一致则拆页”的判断。
- 将面板裁剪结果和原始 Figure 的对应关系写入证据模型，保证可追溯和可回归。

### 第二优先级：使用一篇原始研究论文做盲测

- 选择包含条件优化、底物范围、控制实验、机理研究和 Supporting Information 的论文。
- 在用户尽量少干预的情况下自动生成第一稿。
- 记录每一处用户修改，并区分内容理解错误、Figure 解析错误、版式选择错误和审美偏好。
- 将修改转化为回归用例，防止优化一类页面时破坏另一类页面。

### 第三优先级：补齐比赛演示层

- 将需求问答做成按钮/选项式流程。
- 展示规划建议并提供“批准、修改、重新生成”。
- 提供生成进度、预览、下载和失败诊断。
- 按比赛接口文档封装上传、状态查询和产物返回。

## 当前完成度判断

- **单篇示范稿的视觉效果：约 80%–85%**。已经可以展示和继续人工修改。
- **端到端工程骨架：约 70%–75%**。主要接口、状态机和产物链路已经存在。
- **陌生论文自动生成的稳定性：约 45%–55%**。这是当前最大的缺口。
- **比赛可提交产品：约 60%–70%**。还需要自动版式判断、第二论文盲测、交互演示和接口验收。
