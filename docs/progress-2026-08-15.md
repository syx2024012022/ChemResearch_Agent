# ChemResearch Agent 开发进度记录

更新时间：2026-08-15

## 1. 项目目标

构建面向有机化学文献组会汇报的端到端 Agent：

`上传论文 → PDF 解析 → 文献分析 → 用户交互确认需求 → 规划并审批 → 内容编排 → 生成可编辑 PPTX → 自动与人工检查`

首版坚持证据可追溯、Planning 必须与用户交互、规划必须经用户批准、Composer 不得改变已批准叙事顺序。

## 2. 当前已实现

### PDF 解析

- 已接入 PyMuPDF 生产解析器。
- 支持页码、文本块、坐标、Figure 图注和图片裁切。
- 当前 N-BPA 综述共 13 页，Figure 1–11 均已提取。
- 新增论文首页 TOC Graphic / Graphical Abstract 专项提取。
- 当前样本文献 TOC 图已成功识别。

### Literature Analysis

- 已实现结构化 Literature Skill 和证据绑定。
- 所有明确结论必须引用真实 `source_id`。
- 未配置外部模型 API Key 时返回明确 503，不生成伪造结果。
- 本轮全流程调试使用了基于真实 Figure 图注、页码和 DOI 的人工校核分析草案。

### 分步用户需求访谈

- 已从一次性表单改为 Agent 主导的逐步问答。
- 当前交互顺序：用途、场合/听众、语言、论文重点确认、是否需要讲稿、特殊要求、Agent 扩展理解确认、页数区间。
- 已取消强制询问汇报时间。
- 页数改为区间偏好，例如“约 10 页（9–11 页）”，由 Planning 根据文章内容决定实际页数。
- 重点由 Agent 根据论文提出候选，用户负责确认、删除、增加或改写。
- 特殊要求同时保留用户原话和 Agent 扩展理解；用户确认后才进入正式需求。
- 后续前端可把问题类型直接渲染成按钮、多选框、数字输入和文本框。

### Planning

- Planning 仅在文献分析和用户访谈完成后运行。
- 已支持页数区间，不再机械计算“每页多少秒”。
- 已增加重复结论消除、按证据页码排序和多组 Figure 拆页。
- 规划必须由用户明确批准后才能进入 Composer。
- 当前 N-BPA 规划为 11 页，处于“约 10 页”的 9–11 页区间内。

### Composer、Renderer 和验证

- 已实现规则 Composer、模板注册表和 Artifact Tool PPTX Renderer。
- 输出为可编辑 `.pptx`，文字、标题、页码和基础元素可修改；论文 Figure 作为图片嵌入，可移动、缩放和替换。
- 已支持 speaker notes 中的最小 `[Sources]` 来源记录。
- 用户不需要讲稿时，不生成逐页讲述正文，但仍保留来源。
- 已实现 PPTX、逐页 PNG、布局 JSON 和 artifact 持久化。
- 当前自动测试：24 项全部通过。

## 3. 今晚确认的通用 PPT 规则

以下规则已写入 `docs/presentation-standard.md`，并进入领域模型或 Composer 门禁：

1. 禁止任何纯文字页，包括单独的核心问题页、章节过渡页和纯文字总结页。
2. 每页必须有论文图、反应式、机理图、谱图、数据图或其他来源明确的视觉主体。
3. 视觉内容应占页面主要面积；文字只保留短标题、必要标签和极少量解释。
4. 文字过多时优先删减、拆页或更换布局，不通过缩小字号硬塞。
5. 首页必须包含论文标题、作者、期刊/年份/DOI 和 TOC Graphic。
6. 不允许拉伸、变形或模糊化化学图。
7. 所有非平凡结论和外部素材保留来源记录。

用户提供的《标准模板.pptx》已保存为：

`assets/templates/chem_group_standard.pptx`

模板特点：

- 16:9；
- 蓝色分子横幅；
- 清华大学基础分子科学中心标识；
- 白色内容画布；
- 右下角页码；
- 当前源文件只有 2 页：封面和空白内容母页。

由于模板没有现成的图片占位布局，下一步需要在保留品牌、母版、字体和页码的基础上扩展可复用布局，而不是简单替换文字。

计划建立的默认布局：

1. 论文首页：标题、作者、期刊/DOI、TOC 图；
2. 单张横图主导；
3. 两张图并列；
4. 纵向图 + 两至三条短逻辑；
5. 机理图 + 实验依据图；
6. 总结图，不使用纯文字总结。

## 6. 当前产物与质量判断

已生成过一套 11 页可编辑 PPTX，用于验证完整工程闭环。该产物证明了 PPTX、图片、notes、预览和验证链路可运行，但视觉效果未达到课题组交付标准，不作为最终模板成果。

已发现并修复的视觉问题包括：

- 纯文字核心问题页过空；
- 双图页面只显示一张图；
- 纵向图片直接居中导致大面积空白；
- 多页重复显示标题和正文；
- 首页缺少论文元数据和 TOC 图。

新增模板和“禁止纯文字页”规则后，旧产物不应作为后续视觉基准。

## 7. 已知工程问题

1. Windows 下 Artifact Tool 在完整生成 PPTX 和全部预览后仍返回非零退出码 `3221226505`。输出文件、11 张预览和 PPTX 包结构均存在，但该运行时兼容问题需要单独排查。
2. `ppt-master` 的系统 Python 缺少 `python-pptx` 和 PyMuPDF；当前已使用项目 `.venv` 完成模板和 PDF 只读分析，没有额外安装依赖。
3. 模板检查脚本依赖 Unix `unzip` 命令，在 Windows 上无法直接完成；已使用其他解析和渲染工具确认模板为 2 页。
4. 当前规则 Planning 仍是 MVP。正式版本最好由结构化模型生成标题和内容分配，再由程序执行页数、证据、重复和视觉门禁。

## 8. 下一步建议

下一次继续时按以下顺序进行：

1. 将《标准模板.pptx》扩展为 5–6 种可复用的图片主导布局；
2. 把模板选择和布局容量接入 `TemplateRegistry`；
3. 删除当前规划中的纯文字核心问题页，或将问题融入有图的背景页；
4. 使用新模板重新生成 N-BPA 全套 PPTX；
5. 逐页检查图像比例、裁切、字号、空白、标题换行和 Figure 对应关系；
6. 让用户复核化学内容和课题组风格；
7. 修复 Artifact Tool 在 Windows 上的异常退出码；
8. 后续增加一篇含条件优化、底物范围、机理实验和 SI 的原始研究论文作为第二基准。
