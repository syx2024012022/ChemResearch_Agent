# ChemResearch Agent 当前进度与长期原则

更新时间：2026-08-16

## 当前端到端能力

项目已经跑通：`PDF 解析 → 文献分析 → 分步需求访谈 → Planning → 用户批准 → Composer → 可编辑 PPTX → 自动验证`。

- PDF 主路线为 PyMuPDF，支持正文、页码、坐标、Figure/Scheme/Table、TOC Graphic 和 DOI。
- Literature Skill 使用结构化证据模型；无来源结论不得进入规划或 PPT。
- 需求交互由 Agent 逐步提问，重点由 Agent 根据论文提出、用户确认；不强制询问演讲时间，页数使用“约 10 页”等柔性范围。
- Planning 只能在需求确认后运行，且必须经用户批准才能进入 Composer。
- Renderer 使用 `@oai/artifact-tool` 输出可编辑 PPTX、逐页 PNG、布局 JSON、montage 和 speaker notes 来源。
- 默认模板为 `assets/templates/chem_group_standard.pptx`；默认可见语言为英文，Arial；中文使用 SimHei。
- 当前回归测试为 32 项通过。

## 用户确认的长期 PPT 原则

1. 有机组会以科学问题、反应设计和机理为主，不把听众熟悉的条件筛选机械地当作叙事中心。
2. 不必严格按照论文顺序。必要时先讲清大致反应设计和完整催化循环，再回到优化、scope 和实验依据。
3. 禁止纯文字页；每页都必须有论文原图、反应、机理、谱图、表格或数据证据。
4. 图多字少、页面较满。判断“占满”看有效图形面积，不看图片容器是否全宽。
5. 页数是柔性目标，版式质量是硬要求；宁可合理拆页，也不把不相容的长图、宽图和不同语义材料强行拼接。
6. 普通单图如果仍显空，可右移放大，并在左侧使用论文原文压缩出的短句和浅灰圆形强调区。
7. A–D/A–E 多面板整图通常不加旁白，裁白边后放大到接近占满白色内容区。
8. 纵向长图存在可靠边界时应裁分重组：两部分横排；四面板可按 `(A+B)/(C+D)` 横排；不得切断结构、箭头、坐标、图例或让面板标签与内容分离。
9. 宽图可贴近白色区域左右边缘；无额外说明的图可贴近白色区域上下边缘。
10. 两图并排优先统一视觉高度；宽度差异较大时顶部对齐，关键证据图可获得更大宽度。
11. 多图组合必须使用安全裁白边后的图片，不能让图片内部白边抵消放大效果。
12. 机理/表征与 scope/拓展应用承担不同叙事任务，素材足够时分别成页。
13. 首页包含完整论文标题、作者、期刊/年份/DOI 和 TOC Graphic；无独立 TOC 时使用最能概括论文贡献的原论文视觉，并注明其来源性质。
14. 新增英文使用 Arial，中文使用 SimHei；深蓝标题栏内标题必须为白色。
15. 可见表述尽量沿用论文原文术语和语气；不得把 proposed、suggested、may 等升级成确定结论。
16. speaker notes 保留 `[Sources]`；需要讲稿时可加入中文讲稿，不需要时只保留来源。

## 已固化到 Composer/Renderer 的规则

- `single_with_callout`：单图右移、左侧短摘录与灰色圆形。
- `multipanel_full`：多面板整图铺满。
- `two_panels_fill`：两面板横排，宽度不同时顶部对齐。
- `panel_triptych`：三面板紧凑组合。
- `weighted_two_images`：关键证据图获得更大宽度。
- `stacked_mechanism_overview`：反应设计概要与完整催化循环上下组合。
- 四面板纵向长图可在可靠空白带处按 2+2 裁分。
- 多图版式正式使用 `trimmed_asset_path`，避免原始裁图内部白边。
- Table 裁图保留脚注和配体结构，并避免带入下一段正文。
- Validator 已增加最终渲染视觉覆盖门禁：逐行计算白色内容区内真实非白内容的横向跨度，平均覆盖低于 0.25 时返回 `insufficient_visual_coverage`，不再以图片容器尺寸代替有效图形面积。
